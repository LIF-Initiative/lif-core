# Degraded learner records

`dev-single-org-degraded/` holds 12 deliberately flawed copies of valid synthetic learners from `dev-single-org/`, for testing how LIF handles bad source data. The flaws are intentional: do not fix the `.json` files in this folder. [`KEY.md`](KEY.md) lists every valid and degraded case in detail. No script loads `dev-single-org-degraded/`, and the default demo seed (`dev-single-org/`) doesn't include it. All people, student numbers, and contact details are invented.

## Before you load anything

- Load `dev-single-org-degraded/` only into a database of its own. Each of its files except `Marcus-Webb-100125.json` (D11B) has the same name and student number as a valid learner in `dev-single-org/`.
- No record has schema errors beyond those lif-core's original `dev-single-org` records also have. Each flaw is in what the data says, so it reaches the component under test instead of failing at parse time.
- "Proposed handling" is what LIF should do with each record. It is a proposal: the demo's MongoDB loader (`projects/mongodb/entrypoint.sh`) imports records without checking them.

## Using them (optional)

1. Set `SEED_DATA_KEY` to `dev-single-org-degraded` on the `mongodb` service and rebuild its image; the Dockerfile copies `sample_data/` into the image at build time. The loader then imports only that folder and replaces the collection (`mongoimport --drop`).
   - `development/docker-compose.yml`: `lif-identity-mapper-db` reads the same variable, so change the `mongodb` service's default instead of exporting it in the shell.
   - `development/advisor-demo-1org/docker-compose.yml`: the database is kept in the `mongo_data` volume, and seeding runs only when that volume is empty. Removing the volume deletes that local database.
2. To list these learners in the Advisor login and the Learner Data Export picker, put the lines in `demo_personas-degraded.py.txt` into `_DEMO_PERSONAS` in `components/lif/demo_personas/core.py`, in place of the 24 synthetic learners already there (student numbers 100101–100124): the emails are the same. D11A and D11B share one email, so the Advisor login can't tell them apart. `test/components/lif/demo_personas/test_core.py` asserts the persona count and IDs.

These steps follow the loader and compose files at commit `0354d64` (2026-11-18) and have not been run.
